## 1. 平台概览

AlphaIO 是围绕 A 股研究提供量化模型、数据接口、可视化预览与 AI 接入的平台。其主线是将行情、资金、筹码、题材和策略规则组织为可订阅的功能，再通过网页、GraphQL、RESTful 和 MCP 向研究者及开发者交付。

从当前产品结构看，平台不只是数据目录，还覆盖三个层次：

- **数据与规则研究**：基础行情、资金、涨停连板、筹码、指数板块、资讯，以及十类盘后形态规则。
- **AI 与研究自动化**：AI 每日总结、Hermes 专业投研报告，以及供外部 Agent 使用的 MCP、Skill 和 LLM Doc。
- **独立盘中工具**：智T引擎、智T·QMT、超级分时、龙头分时，分别涉及信号提醒、本地执行衔接和分时观察。

官网与 FAQ 仍以“盘后模型、API、Demo”为主要定位，但特色产品已经描述盘中信号和飞书推送。介绍平台时应保留这一区别，不能简单概括成“全部仅盘后”，也不能将全部商品理解为实时交易工具。详见第 9 节的口径核对。[S1][S2][S9][S11]

### 适用对象

| 使用者 | 主要使用方式 | 能获得的价值 |
| --- | --- | --- |
| 个人研究者 | 网页预览、图表、规则样本、日报 | 集中查看数据与研究线索，减少跨页面整理 |
| 量化开发者 | GraphQL / RESTful | 将结构化数据接入脚本、回测、报表与流水线 |
| AI Agent 使用者 | MCP / Skill / LLM Doc | 让 AI 在账户权限范围内查询数据并组织结果 |
| 多标的盘中观察用户 | 独立订阅分时工具或智T引擎 | 观察分时结构、接收提醒、人工核对 |
| 有 QMT 环境的用户 | 客户侧 Worker 与成交回写方案 | 连接本地执行和复盘；完整交付状态需另行确认 |

以上为依据页面能力归纳的适用场景，不代表效果或收益保证。

## 3. 对接方式与开发者能力

### 3.1 四条接入路径

| 方式 | 已核实的入口 | 适合场景 | 主要约束 |
| --- | --- | --- | --- |
| 网页工作区 | 功能详情、Demo、GraphiQL | 浏览、筛选、理解字段和调试查询 | 权限、预览窗口和额度仍生效 |
| Shop GraphQL | `POST https://www.alphaio.vip/shop-api` | 自建脚本、灵活选择字段与查询条件 | 登录 Token、`channel`，处理 GraphQL `errors` |
| RESTful | 日线示例：`POST https://oss.alphaio.vip/api/query/daily` | 常规 HTTP 集成与跨语言调用 | 严格使用接口对应路径、参数和 `columns` |
| MCP | `https://oss.alphaio.vip/api/mcp` | 外部 AI Agent 调用授权工具 | Streamable HTTP，不能绕过订阅和限流 |

GraphQL 文档提供 curl、Python 示例；RESTful 示例语言选择包含 curl、Node.js、Python、Java。平台提供的是 HTTP 协议与示例，本次未确认有独立发布、版本化维护的官方 SDK。[S3][S4][S5]

### 3.2 鉴权、参数与数据结构

- GraphQL 使用 `Authorization: Bearer <TOKEN>`；RESTful 日线页支持 `x-quants-token` 或 Bearer。
- 请求携带 `channel: hps-quants`。文档强调频道键为 `channel`，不能替换为 `vendure-token`。
- RESTful 的 `apiName` 位于路径；Body 使用 `tsCode`、`tradeDate` 等 camelCase 参数，并要求非空 `columns`。
- 日线接口提供单日与日期区间、`limit`、`offset`；文档写明该接口分页大小默认/上限为 100。这是日线接口示例，不应推广到所有 API。
- 日线返回说明包含 `totalItems`、`items`、价格字段、成交量与成交额，并注明成交量单位为“手”、成交额为“千元”。
- 页面可生成带当前会话凭证的配置与示例；对外分享文档或提交代码时应使用占位符，不复制实际 Token。

以上为文档核实，未执行真实接口调用验证。[S3][S4]

### 3.3 配额设计

单独购买 API 时，平台主张按 `featureCode` 独享分钟配额；购买数据包时，包内接口共享该套餐的桶，套餐与其他能力保持独立。另有 IP 维度限额；不同入口展示的数字并不一致。[S1][S3][S6]

调研时的具体例子：

- MCP 与 Skill 总说明写明单工具/单接口 **20 次/分钟**。
- 日线、AI 日报和 Hermes 的 API 工作区显示 **30 次/分钟**、IP **60 次/分钟**。
- 基础数据 VIP 方案卡显示 **240 / 480 次/分钟，包内共享**。

这些数字可能涉及不同层级或文案未同步，本次未验证实际网关执行规则。因此不能对外承诺全站统一限速，也不能把套餐额度直接等同于 MCP 单工具吞吐。接入时应核对具体权益、入口限制与实际响应，遇到 429 分批和退避。[S3][S5][S6]

## 4. AI 支持

### 4.1 外部 Agent：MCP

开发者中心提供多客户端配置页，包括 Cursor、Codex、Claude Code、Claude Desktop、VS Code、Windsurf、Cline、Trae、Qoder、WorkBuddy、Cherry Studio、OpenClaw；豆包页签标注暂不支持。这里指官网列出了配置说明，不代表本次逐一完成了客户端连接测试。[S3]

MCP 工具最终调用相同的 Shop GraphQL 能力，沿用账号授权、交易日范围和调用配额。文档提醒，新增订阅后 Agent 的本地工具缓存可能未更新，需要刷新或重新加载配置。[S3]

### 4.2 Skill 与面向模型的文档

平台提供 `alphaquant-openapi-integration` Skill 模板，规定 AI 先读接口文档，再按认证头、参数位置和字段约束调用，遇到限流退避，最后输出联调摘要。API 工作区另提供 GraphQL / RESTful 的 **LLM Doc**，便于将当前接口说明送入 Agent 上下文。[S3][S4]

Skill 是调用规范和提示模板，不是新的数据权限；也不能据此认为平台支持任意第三方模型的托管、充值或推理服务。

### 4.3 平台内置 AI 产物

| 能力 | 页面描述 | 交付与计费 | 验证范围 |
| --- | --- | --- | --- |
| AI 每日总结 `ai_daily_brief` | DeepSeek 或配置的 LLM 生成盘后五段式市场总结，与飞书正文同源 | API 文档显示月卡，提供 GraphQL / RESTful / MCP 入口 | 已读文档，未验证每日实际生成、推送或内容质量 |
| Hermes 专业投研报告 `hermes_agent` | 技术、资金、情绪、筹码、风险五维评分，多标的横向比较 | 按调用次数包；异步任务，返回 `taskId`；页面可回看近期任务 | 已读产品与接口说明，未提交付费分析任务 |

Hermes 页面列出 50 / 200 / 1000 次包，支持叠加购买；界面说明成功后扣 1 次、失败不扣次。页面提到约 10 秒异步回显入参，但这不能作为完整报告产出时延 SLA。开发者可按 `taskId` 查询任务状态，不能将提交成功直接视为报告完成。[S7][S8]

## 8. 建议的使用路径

1. **明确需求**：只看数据、规则复盘、AI 整理，还是使用独立盘中工具。
2. **从功能大厅找对应能力**：核对字段、更新日期、预览状态和是否需要多个接口。
3. **选择交付方式**：网页验证口径，GraphQL/RESTful 接脚本，MCP/Skill 接 Agent。
4. **匹配计费单位**：少数接口考虑单品，多接口比较数据包；盘中工具按槽位，Hermes 按次数。
5. **确认关键边界**：实际额度、预览延迟、试用资格、自动化凭证、QMT 发布状态及售后承诺。
6. **小规模验证后扩展**：核对字段单位、日期范围和响应错误，再增加查询量；AI 结论保留数据来源和研究假设。

这是一条基于页面能力提出的使用建议，不表示本次已完成端到端接入验证。
