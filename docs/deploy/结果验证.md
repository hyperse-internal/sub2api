# 结果验证

在 [服务器部署.md](./服务器部署.md) 第 3 步之后执行。变量见 [生产部署.md](./生产部署.md#会话变量)。

```bash
"${SSH[@]}" "$HOST" "set -euo pipefail
/opt/sub2api/bin/server --version
systemctl is-active sub2api
systemctl show -p NRestarts --value sub2api
curl -fsS -o /dev/null -w 'public=%{http_code}\n' https://ai.alphaio.vip/health
B=/opt/sub2api/backup/$TS
for f in config.yaml .env .installed; do cmp /opt/sub2api/\$f \$B/\$f; done
PID=\$(systemctl show -p MainPID --value sub2api)
tr '\0' '\n' < /proc/\$PID/environ | grep -qx 'DATA_DIR=/opt/sub2api'
test ! -e /app/data
tail -n 30 /opt/sub2api/logs/stderr.log
grep -wE 'ERROR|FATAL|PANIC' /opt/sub2api/logs/sub2api.log | tail -n 20 || true
echo ok
"
```

## 通过标准

| 项 | 期望 |
| --- | --- |
| `--version` | commit 与 [构建.md](./构建.md) 里 `git log -1` 一致 |
| `is-active` / `NRestarts` | `active` / `0` |
| 公网 health | `public=200` |
| 配置比对 | `cmp` 无输出（三份配置与备份相同） |
| 进程环境 | 含 `DATA_DIR=/opt/sub2api`，`/app/data` 不存在 |
| 日志 | `stderr.log` 末尾和 `sub2api.log` 的 `ERROR` 行，时间都早于本次重启 |
| 结尾 | 输出 `ok` |

再用管理员账号登录 `https://ai.alphaio.vip`，确认用户、渠道、设置都在、管理页面正常。

## 失败处理

| 现象 | 处理 |
| --- | --- |
| health 不通、`NRestarts` 增长、日志有迁移 checksum 错误 | 回滚二进制 |
| 本机正常、公网非 200 | 查 Nginx，不要改 `config.yaml` |
| `cmp` 报配置不同 | 立即停止操作，从 `backup/$TS/` 恢复配置后再评估 |
| 页面是旧的或缺管理页 | 漏了 `-tags embed` 或传错包，重新构建 |
