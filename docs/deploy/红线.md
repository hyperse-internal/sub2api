# 红线

覆盖升级生产时违反任一条都可能丢会话、毁配置或清数据。新开会话部署前先过一遍。

1. **只替换** `/opt/sub2api/bin/server`（以及按流程更新的 `/opt/sub2api/website/`）。不要重跑安装向导。
2. **不要覆盖** 服务器上的 `config.yaml`、`.env`、`.installed`。`docs/deploy/config/` 只是仓库内对照副本。
3. **不要** 删除 `.env` 里的 `DATA_DIR=/opt/sub2api`，也不要加回 `AUTO_SETUP`。缺少 `DATA_DIR` 时，只要 `/app/data` 存在，程序就会改读那里的配置。
4. **不要** `FLUSHDB`、改 `redis.db`（现为 `1`）、清空 PostgreSQL。
5. **不要** 改 `jwt.secret`、TOTP 相关密钥（会话与二次验证会失效）。
6. **不要** 在生产机上 `go build` / 编前端 / 编 website；本机或 CI 构建完成后再上传。
7. **必须** `go build -tags embed`，否则管理面板不会打进二进制。website **不要** embed 进 Go；由 PM2 + Nginx 提供 `/docs`。
8. Go：上传写到 `server.new` → sha256 与本地一致 → 再 `mv` 成 `server` → 再 `systemctl restart`。website：rsync/解压完成后再 `pm2 reload alphaio-docs`。
9. **不要** 为回滚删除 `.installed` / `config.yaml`。两者都不存在时进程会进入安装向导，经 Nginx 对公网暴露。
10. **只部署已推送到远端的提交**。未明确要求时，不要改生产分组倍率 / 价目 / 账户 `extra`。
11. **只允许从 `main` 分支发布**。不要用 feature / hotfix / 其他分支的构建物覆盖生产；发布前确认当前提交已在远端 `main` 上。
12. 生产密钥、JWT、密码可以存在 git 里（`docs/server/server.pem`、`docs/deploy/config/`），但**不要**输出到聊天：不要 `cat` 这些文件，查配置时只看键名或用 `grep -c` 确认是否存在。
13. **不要** 对公网暴露 website 的 `3001`；仅 `127.0.0.1`，由 Nginx 反代 `/tools`、`/cn/tools`、`/docs`、`/cn/docs`、`/docs-assets/`、`/docs-api/`。website 营销首页是 `/tools`，不要用 `/`（与 Go 面板冲突）。
14. **不要** 把文档搜索挂在 `/api/search`（会与 Go `/api/v1` 冲突）；必须用 `/docs-api/search`。
