# 服务器部署

备份 → 上传 → 替换 → 重启。变量 `PEM` / `HOST` / `SSH` / `TS` 见 [生产部署.md](./生产部署.md#会话变量)。

## 1. 备份

只在本次部署开始时执行一次。替换后失败需要重试时，从第 2 步开始，否则新备份里存的就是坏掉的新包。

```bash
"${SSH[@]}" "$HOST" "set -euo pipefail
B=/opt/sub2api/backup/$TS
install -d -m 700 \$B
cp -a /opt/sub2api/bin/server /opt/sub2api/config.yaml /opt/sub2api/.env /opt/sub2api/.installed \$B/
sudo -u postgres pg_dump -Fc -d sub2api > \$B/sub2api.dump
chmod 600 \$B/sub2api.dump
ls -l \$B
"
```

## 2. 上传

```bash
scp -i "$PEM" -o IdentitiesOnly=yes -o StrictHostKeyChecking=accept-new \
  backend/server "$HOST:/opt/sub2api/bin/server.new"
LOCAL_SHA="$(shasum -a 256 backend/server | cut -d' ' -f1)"
"${SSH[@]}" "$HOST" "echo '$LOCAL_SHA  /opt/sub2api/bin/server.new' | sha256sum -c -"
```

sha256 不一致：重新 scp，不要进入第 3 步。

## 3. 替换并重启

```bash
"${SSH[@]}" "$HOST" 'set -euo pipefail
chmod 755 /opt/sub2api/bin/server.new
mv /opt/sub2api/bin/server.new /opt/sub2api/bin/server
systemctl restart sub2api
for i in $(seq 1 30); do
  curl -fsS http://127.0.0.1:8080/health >/dev/null 2>&1 && break
  sleep 2
done
curl -fsS http://127.0.0.1:8080/health
'
```

60 秒内 health 不通即失败（迁移较多时启动会慢一些），直接回滚。

## 4. 回滚

默认只回滚二进制，不回滚数据库；`pg_restore` 会丢掉升级后写入的数据，仅在明确要求时评估。

```bash
"${SSH[@]}" "$HOST" "set -euo pipefail
cp -a /opt/sub2api/backup/$TS/server /opt/sub2api/bin/server
systemctl restart sub2api
for i in \$(seq 1 30); do
  curl -fsS http://127.0.0.1:8080/health >/dev/null 2>&1 && break
  sleep 2
done
curl -fsS http://127.0.0.1:8080/health
"
```
